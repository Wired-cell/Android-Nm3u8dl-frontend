[ ] 3. Download start: "mp4decrypt not found" (reproduced by the user's latest 1.4.9 log).
    Previous attempted fix: Passing libmp4decrypt.so as a separate --decryption-binary-path argument did NOT resolve the error. Do not count that attempt as fixed.
    Root-cause finding from upstream Program.cs: the generic "mp4decrypt not found" message is thrown only when DecryptionBinaryPath is null/empty and PATH lookup fails. If a supplied path is non-empty but missing, upstream throws FileNotFoundException containing that actual path instead. Therefore the latest log strongly indicates the binary-path option is not reaching/binding in the engine.
    Change made in 1.5.0: Pass --decryption-engine=MP4DECRYPT and --decryption-binary-path=<canonical absolute path> as single argv tokens using System.CommandLine's --option=value form. Add a visible diagnostic line showing the exact configured mp4decrypt path before launch. Keep the real executable (not the launcher) as the configured binary.
    Verification: Code committed; not yet verified by CI or on an Android device. Require CI APK verification and a real encrypted MPD download test before marking resolved.
