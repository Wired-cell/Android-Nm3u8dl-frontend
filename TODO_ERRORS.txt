[ ] 3. Download start: "mp4decrypt not found" (reproduced by the user's 1.5.0 device test).
    Root cause confirmed from the exact bundled upstream tag v0.6.0-beta:
      - Program.CheckMediaTools() handles DecryptEngine.MP4DECRYPT by unconditionally calling GlobalUtil.FindExecutable("mp4decrypt").
      - It ignores option.DecryptionBinaryPath entirely in that release.
      - GlobalUtil.FindExecutable() searches Environment.CurrentDirectory, the engine directory, then PATH. The app's current directory is files/native, while the actual executable is extracted as libmp4decrypt.so into nativeLibraryDir.
    Fix committed for 1.5.1:
      - At startup, create files/native/mp4decrypt as a symbolic link to the executable lib/arm64/libmp4decrypt.so in nativeLibraryDir.
      - This gives the old engine the exact filename and current-directory location it searches, while the symlink target remains on Android's executable native-library mount (not the app data noexec mount).
      - Run --help through the symlink itself and log/verify that its canonical target is the packaged executable.
      - Check the symlink again before starting each download.
    Status: Source fix committed; NOT yet runtime-verified. CI build and an encrypted MPD device download are still required. If the device rejects symlink execution, next step is to patch/rebuild the engine to honor DecryptionBinaryPath rather than claim success.
    Verification required: Successful encrypted MPD download on Android, not merely a successful APK build.

[ ] 4. Progress visibility / background execution.
    Changes committed for app version 1.5.2 (versionCode 17):
      - Download process moved out of MainActivity into DownloadService.
      - Service calls startForeground immediately and keeps an ongoing Downloads notification while the engine runs.
      - Notification updates with emitted engine output; percentage is shown when the engine emits a percent value, otherwise an indeterminate progress indicator is used.
      - Notification includes a Stop action; app Stop button controls the same service.
      - Runtime POST_NOTIFICATIONS permission is requested on Android 13+; if denied, Android may hide the notification from the drawer although the foreground service remains visible in system task manager.
      - Download process is no longer tied to Activity destruction, so it can continue when app is backgrounded. Android battery/vendor restrictions can still affect long-running transfers.
      - Signed URL query parameters are suppressed in notification text.
    Status: source changes committed; CI build and device background/notification test pending. Verify notification updates, Stop action, completion notification, and return to app log on device.
